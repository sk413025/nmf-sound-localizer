Log interpretation (why the “argmax shifted” report happened)
- Moving-average smoothing is a convolution over the discrete angle grid, which can move the index of the maximum when the peak is narrow or asymmetric.
- Therefore, if smoothing is used for readability, the only safe “argmax/peak” marker is the one computed from raw values.
- This run disables smoothing, confirming the underlying model-native QK argmax is correct at 145°; the earlier discrepancy was a visualization artifact.

Cross-experiment analysis (commit hashes; causal pattern)
- Original B3 semantics are stable across v3/v4/v6 (commits 0590b12, b8e1148, c0cb7eb) BECAUSE they plot `scores_expert` directly and do not smooth peaks.
- Proxy frequency panels were introduced in v9 (commit 58118bf); QK can appear “wrong” there DUE TO the definition changing from model-native QK to projection-weighted proxy.
- Our equivalence-preserving band decomposition baseline (commit d4e9016) and 5-line-plot variant (commit afac0a1) restored the correct semantics; this run refines the visualization guardrail so “argmax correctness” is not undermined by smoothing.

Physical / mathematical analysis (first principles)
- Physics baseline:
  - Because full-band is `Σ_m |(D^T y)[e,m]|`, naive “per-band abs then sum” is not equivalent (`|a+b|≠|a|+|b|`), so we use sign-aligned band contributions to reconstruct the full-band value.
- Model-native QK:
  - Because `scores_expert` is a non-linear Transformer output, it is not frequency-separable; IG provides an additive attribution with completeness (up to numerical integration error).
- Visualization:
  - Smoothing is a linear filter that changes the function being plotted; the argmax of a smoothed curve is not guaranteed to match the argmax of the raw curve.

Extracted principles
- Never claim “argmax/peak moved” if the curve was smoothed; compute argmax on raw values.
- For frequency-band interpretability of non-linear model outputs, use attribution (IG) and label it explicitly; do not relabel proxies as model-native.
- Keep decomposition equivalence auditable: ship `checks.json` + `code_state.json` with SHA256 and dataset fingerprint.

Next steps
