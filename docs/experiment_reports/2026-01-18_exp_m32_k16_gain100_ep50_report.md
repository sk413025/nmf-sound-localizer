# Experiment Report — exp_m32_k16_full_gain100_ep50 (Jan 18, 2026)

## Summary
This run reruns the M=65 (lags −32..32), K=16, Tw=16 pipeline with **Gain=100** applied consistently in both trajectory generation and evaluation to avoid the soft-metric epsilon-floor artifact.

Key outcomes (evaluation on 10 clips, angle=90°):
- With Gain=100, the **soft capture ratios** no longer collapse in Mids/Highs due to numeric flooring.
- At **K=16**, DT and OMP converge to the same capture ceiling for every band (DT ≈ OMP), with band ceilings decreasing toward higher frequencies.

## Results (band table excerpt)
Metric definition in eval: per-frequency ratio

\[
\text{capture}(k) = \frac{\|\hat{Y}_k\|^2}{\|Y\|^2 + 10^{-6}}
\]

At K=16:
- Sub-Bass: DT=1.0000, OMP=1.0000
- Bass: DT=1.0000, OMP=1.0000
- Low Mids: DT=1.0000, OMP=1.0000
- Mids: DT=0.9971, OMP=0.9971
- Upper Mids: DT=0.9807, OMP=0.9807
- Presence: DT=0.9464, OMP=0.9464
- Highs: DT=0.9241, OMP=0.9241

At small K (e.g., K=1), DT often exceeds OMP (efficiency > 100%). This is possible because DT is not constrained to follow OMP’s greedy selection path and may find atoms that improve early-step capture more quickly.

## Physical / mathematical interpretation
- Gain=100 does **not** change SNR; it changes absolute energy scale so the fixed epsilon (1e−6) does not dominate denominators.
- The decreasing ceiling with frequency is consistent with reduced effective controllability using coarse STFT-frame lag atoms and/or reduced mic↔LDV coupling in high frequencies.
- The “too good to be true” concern at K=16 is mitigated by the degrees-of-freedom observation: when K≈Tw, per-frequency least-squares can behave like an interpolator over a short window (especially if dictionary columns are sufficiently independent).

## Limitations
- This evaluation is **in-distribution** relative to trajectory generation (same dataset roots).
- Reported validation accuracy is not a clean generalization metric because training uses a per-frequency flattened dataset with `random_split`, which likely mixes samples from the same underlying time-window block across train/val.
- RTG in evaluation is computed from residual energy over the observed LDV window $Y$. This is not leakage if $Y$ is available at inference, but it is a **lookahead / non-causal** feature if deployment requires streaming decisions without access to the full Tw-block.

## Next steps
- Add clip/window identifiers into trajectory blocks so we can enforce and verify clip-level splits (train/val/test) and quantify leakage precisely.
- Add a held-out evaluation angle or held-out clips to measure generalization.
- Replace oracle RTG with a deployable proxy (estimated from mic-only statistics) if deployment realism is required.
