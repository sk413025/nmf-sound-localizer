# Task Lifecycle

This is the default lifecycle for agent-executed work in the branch.

## 1. Intake

- identify the manuscript-facing objective
- identify whether code, figures, or results are only substrate
- choose the right contract and skill

## 2. Framing

- pick a role
- choose or adapt a task packet
- define outputs, acceptance criteria, and handoff target

## 3. Execution

- specialist works within role scope
- evidence is gathered from canonical docs and substrate
- any claim-sensitive change is flagged for review

## 4. Review

- review is required when the task changes claims, submission posture, or governance
- red-team review is required when the task introduces new process, role boundaries, or major narrative change

## 5. Consolidation

- supervisor merges outputs
- unresolved conflicts are escalated
- final milestone summary is prepared for the human approver if needed

## 6. Closure

- run required checks
- confirm outputs satisfy the task packet
- record follow-up tasks if the change is intentionally partial
