## What Landed As A Stable Branch Lesson

### 1. The branch is not only polishing prose

Recent work treated the manuscript as under-architected rather than merely under-edited. The recurring problem was not grammar alone, but whether the paper makes one legible editorial move that a Nature Communications reader can retain after one pass.

### 2. The paper needs an explicit cognitive shift

The branch now treats `old-world belief -> new-world belief` as a mandatory design surface. Local clarity is insufficient if the manuscript still reads like a sequence of technically correct observations instead of one updated understanding of the system.

### 3. Discovery must stay the protagonist

Recent review pressure repeatedly surfaced a drift toward tool-first framing. Stable branch guidance now treats solver, calibration, workflow, and reference-object material as supporting actors unless a packet explicitly declares a method-first paper.

### 4. Results architecture matters as much as sentence quality

The branch now treats `pivot`, `discovery cash-out`, and discovery-vs-tool weight as first-order acceptance surfaces. If no Results transition updates the reader's model, the manuscript is still under-architected even when each section is locally correct.

### 5. Broader significance must be earned through a governed ladder

Recent governance work hardened the rule that the manuscript should move from:

- core discovery
- to an evidence-earned `second-layer discovery`
- to at most one bounded `downstream consequence`

Applications that do not descend from that bridge are out of scope for Nature-facing hardening in this branch.

### 6. Optional leaves should be deleted aggressively

The branch now treats weak application leaves as expendable. If removing the leaf improves editor memory for the trunk and branch, the leaf should disappear rather than compete with the main discovery.
